# T143 合成节点与响应式审阅

本目录仅含虚构入口、节点、队列和资源值，不来自任何真实服务器或研究。
`pbs-nodes-synthetic.json` 刻意混合已知、未知和不一致的节点记录，用于验证读取边界，
不是一个可用于容量规划的集群配置；聚合硬件容量未知时保持未知。

- `free` 但已有 slots 分配、未分配、满配、down、offline。
- 缺失 slots、缺失内存或作业数、零容量、分配超过总量。
- 同一节点的 slots 与内存各自判断，不互相补值。
- 失败、过期、来源歧义、读取错误、从未成功和旧快照由 Playwright 基于此数据派生。

资源详情另有[四档与未配置时限](resource-tiers-4.png)、[五档与非整小时时限](resource-tiers-5.png)、
[六档与四位小时时限](resource-tiers-6.png)。这些数值仅用于检查固定档位顺序、
实际项显示、共享排队上限与精确时间，不是资源配置建议；档位插入顺序故意打乱。
操作表单测试使用假 ag 与模拟响应，覆盖可选档位、四位小时、零时长/超限拒绝和旧四档切换。

本目录的 PNG 是已审阅的静态合成参考图，普通测试不会覆盖它们。
`web/tests/pbs-nodes.spec.ts` 通过 `testInfo.outputPath()` 将本轮截图写入各测试独立的
`web/test-results/` 输出目录（已由 Git 忽略）；测试名与图片文件名对应上述场景。
需要更新静态参考图时，先人工查看本轮输出、确认只有合成数据，再显式复制所需图片，
在 PR 中审阅图片变更；不把测试运行本身当作更新参考图的操作。
这些图片均不能用作真实服务器验收证据。
