## 实现要求

1. 使用已有节点数组，不新增 API、远程查询或监控采样；不为某个入口硬编码节点/资源。
2. 状态与分配独立展示。已知且自洽的数值才能计算剩余 slots 和分配比例；缺失、非法或自相矛盾数据标未知，不补零。
3. 内存只使用快照提供的已分配和总内存；不按节点状态、核数或物理空闲字段推测。
4. 失败、过期、来源歧义或无成功数据的状态沿用现有语义；保留值明确标非实时，不用彩色比例暗示可立即使用。
5. 每入口卡片仍由模型数组动态生成。桌面分别检查四卡与五卡，平板与手机无页面横向溢出；表格可在自身容器横向滚动。
6. 表头、比例图、状态与键盘操作具有可访问名称；不用颜色作为唯一信息；保留已有服务器标签方向键选择。
7. 不修改 Slurm 隐私过滤、作业表、采样请求与审批操作。
8. `resources.tiers` / `own.tiers` 按 `mini/simple/general/complex/max/ultra` 固定顺序呈现。前四档为既有必需配置，后两档可选；只显示实际项，旧四档不补占位。
9. `ag clusters` 的 `resources.max_walltime` 与 `ag-monitor/1` 的 `own.max_walltime` 均为可选正 `HH:MM:SS` 字符串，小时 2–4 位、分秒 00–59。未配置省略，不接受 null、数字、布尔或零时长；显示小时，非整小时保留准确时分秒。缺省显示未配置且调度器仍可能限制。
10. 本人排队上限继续使用 `own.max_queued_cores` 和现有共享账号限额汇总，不新增别名。操作表单接受实际可选档位与四位小时；保持令牌、锁、操作种类和审批流程，最终资源硬限制仍由 ag 执行。
